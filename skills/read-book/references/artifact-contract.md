# 渐进式读书地图产物契约

仅在生成或修订读书地图时读取本文件。保持结构稳定，但让每本书的内容组织服从其真实论证，不强套任何既有地图的章节结构。

方法基线批判参考《如何阅读一本书》的阅读纪律，只保留适合本产品的执行动作；不复制其四层讲解、15 条规则或固定章节结构。

## 目录

```text
<OUTPUT_ROOT>/
├── index.html
├── README.md
└── books/
    └── <中文书名>/
        ├── reading.html
        ├── reading.json
        └── modules/
            └── <module-slug>/
                ├── reading.html
                └── reading.json
```

使用稳定的英文 `module-slug`。不要把原书、解包目录、缓存、截图或备份写入书籍目录。

## 主页面至少回答什么

1. 这是什么书，版本和材料边界是什么。
2. 全书在解决什么问题，怎样展开。
3. 作者的主要观点和论证依据是什么。
4. 哪些人物、力量、概念或阶段之间存在关键关系。
5. 哪些结论来自作者，哪些是报告综合、批判审计或外部背景。
6. 第一轮应该回读哪些原文，为什么。
7. 读者接下来应全读、选读、深挖还是停止。

页面不需要固定章节数量。优先保留单一阅读顺序：首屏结论 → 版本边界 → 全书模型 → 核心观点或主题 → 原文路线 → 批判审计 → 阅读决策 → 已生成深挖。

## `reading.json` 基线

主地图保留以下顶层字段；可以增加书籍需要的字段，但不要用多个字段表达同一事实。

```json
{
  "schema_version": "read-book.v1",
  "artifact_kind": "rapid-reading-map",
  "book": {},
  "source": {},
  "scope": {},
  "reading_contract": {},
  "claims": [],
  "critical_audit": {},
  "module_policy": {},
  "modules": [],
  "generation_audit": {}
}
```

允许兼容已经生成的 `read-book.dogfood.v1`。不要仅为了改版本号重写旧产物。

### `source`

至少保留可获得的来源文件名、格式、SHA-256、字节数、编码或 EPUB 元数据，以及无法确认的版本信息。来源的绝对私有路径不要写入可发布产物。

### `scope`

明确正文纳入范围、排除范围及理由。合订本、个人编辑卷、附录、广告和文本污染必须单独处理。

### `reading_contract`

至少包含主地图目标时间、阅读单元、渐进层级和完成定义。时间是阅读设计预算，不是对所有读者的保证。

### `claims`

每条关键结论使用稳定 ID，并尽量提供原书定位。把内容类型显式标为作者主张、报告综合、批判审计或外部背景；不要用语气暗示来源类型。

### `module_policy` 与 `modules`

- `generation` 固定为 `on_demand_only`。
- 只有真实生成的模块才进入主页面和 `modules` 列表。
- 记录模块 ID、标题、状态、HTML/JSON 相对路径、阅读时间和可选父模块。
- 深挖模块不得改变主地图对原书版本与范围的冻结边界，除非新证据明确要求修订并留下说明。

## 深挖模块

每个模块围绕一个明确问题，至少包含：

- 问题和范围。
- 与主地图的关系。
- 作者原文模型或核心论证。
- 少量连续原文或关键短引，并附定位。
- 报告综合与不能推出什么。
- 必要的外部背景或历史压力测试。
- 最低批判审计。
- 回原文路线和停止条件。

不要把多个相邻兴趣合并成大型专题。用户继续追问时再增加下一层，并在目录中标明父子关系。

## 摘录与语言

- 摘录以理解论证为目的，不以名句收藏为目的。
- 保留作者的限定语、时间条件和概念区分；不要把复杂观点压成口号。
- 先准确复述，再提出批判。批判作者没有主张的观点属于失真。
- 使用具体、平实的中文。少用“赋能、闭环、范式、抓手、全景式、深度洞察”等空泛表达。
- 标题直接说明读者会看懂什么，不使用夸张营销语。

## 视觉契约

- 图必须承载正文难以快速表达的结构、关系、阶段、因果或反馈。
- 主地图通常保留一张全书结构图；只有出现新的独立认知问题时才增加图。
- 图中文字应短而具体，颜色数量克制，箭头方向可解释。
- SVG 采用 `viewBox`，不依赖外部字体、脚本或网络资源。
- 手机端允许 SVG 容器内部横向滚动，但页面本身不得横向溢出，并给出可理解的滚动提示。
- 自动校验不代替目视复核。

## HTML 基线

- 单文件、离线可读，不依赖 CDN。
- 使用正确的 `lang="zh-CN"`、唯一 ID、有效内部锚点和相对链接。
- 正文默认字号不低于 16px；重要交互目标约 44–48px。
- 支持键盘焦点、`prefers-reduced-motion`、打印样式和无脚本阅读。
- 外部资料链接与原文定位分开显示。

## 写入与发布边界

- 生成请求只授权写入阅读地图，不自动授权 Git commit、push、发布或公开原书。
- 私有原书始终留在用户书库；`OUTPUT_ROOT` 只保存原创结构、评论、图示、必要短引文和来源定位。
- 对 README 和首页只做与新增书籍或入口直接相关的最小更新。
